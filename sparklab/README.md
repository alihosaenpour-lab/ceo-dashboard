# Spark Lab | اسپارک لب

پلتفرم واقعی و قابل استقرار برای **فروش محصولات دیجیتال** و **دریافت سفارش پروژه نرم‌افزاری** برای بازار ایران — با رابط فارسی RTL، طراحی Dark Tech، پایگاه داده پایدار، پرداخت امن و تحویل کنترل‌شده فایل.

> گزارش کامل پیاده‌سازی و وضعیت اتصالات: فایل [`REPORT.md`](./REPORT.md)

## پشته فنی

| لایه | فناوری | توضیح |
|---|---|---|
| Runtime | Node.js ≥ 20 (توسعه‌یافته روی 22) | بدون وابستگی بومی (native) — `node:sqlite` داخلی |
| وب | Express 4 + EJS (SSR) | رندر سمت سرور، سبک و سئوپسند |
| پایگاه داده | SQLite (WAL) در `data/sparklab.sqlite` | پایدار روی دیسک — همه داده‌های تجاری اینجا ذخیره می‌شود |
| نشست‌ها | express-session + استور سفارشی SQLite | نشست‌ها پس از ری‌استارت سرور زنده می‌مانند |
| احراز هویت | bcrypt (cost=12) + نقش‌های admin/staff/customer | رمزها فقط به‌صورت هش ذخیره می‌شوند |
| پرداخت | معماری درگاه چندلایه: درایو واقعی زرین‌پال (PG v4) + درگاه آزمایشی محلی | تأیید فقط سمت سرور |
| فایل‌ها | multer + فضای خصوصی `storage/private` | لینک دانلود امضاشده، زمان‌دار و محدود |
| امنیت | helmet (CSP با nonce)، CSRF سفارشی، rate-limit، sanitize-html، اعتبارسنجی سمت سرور | جزئیات در ادامه |
| فونت | Vazirmatn (self-hosted از npm) | بدون وابستگی به CDN خارجی |

## راه‌اندازی سریع

```bash
cd sparklab
cp .env.example .env         # مقادیر امنیتی را پر کنید (openssl rand -hex 48)
npm install
npm run seed                 # جداول + محتوای اولیه + حساب مدیر
npm start                    # http://localhost:3000
npm test                     # آزمون‌های پذیرش (۱۰۵ سنجه) — سرور باید در حال اجرا باشد
```

اگر `SEED_ADMIN_PASSWORD` در `.env` تنظیم نشده باشد، seed یک رمز تصادفی برای مدیر تولید و در
`data/seed-credentials.txt` (با دسترسی ۶۰۰) ذخیره و در کنسول چاپ می‌کند.

## جریان پرداخت (امن)

1. کاربر سبد را در `/checkout` تأیید می‌کند → سفارش با **اسnapshot سمت سرور** قیمت‌ها در DB ثبت می‌شود (`pending`).
2. `initiatePayment` به درگاه فعال درخواست می‌دهد (زرین‌پال: `payment/request.json` با مبلغ **ریال**) و کاربر به صفحه بانک/درگاه آزمایشی هدایت می‌شود.
3. بازگشت → `/checkout/callback`: سرور **خودش** از درگاه استعلام تأیید می‌کند (`verify.json`)؛ مبلغ تأییدشده با مبلغ سفارش مقایسه می‌شود؛ شناسه سفارش و تراکنش بررسی می‌شود.
4. فقط در صورت تأیید معتبر: در یک تراکنش اتمی، payment روی `success` (با **unique index** ضد تأیید تکراری) و سفارش روی `paid` می‌رود، grant های دانلود ساخته و اعلان‌ها ثبت می‌شوند.
5. پرداخت ناموفق → سفارش `failed` و **هیچ دسترسی دانلودی ایجاد نمی‌شود**.
6. اگر هیچ درگاهی پیکربندی نشده باشد، خرید با پیام شفاف ۵۰۳ مسدود است (هرگز موفقیت شبیه‌سازی نمی‌شود).

**درگاه آزمایشی محلی** (`test`) فقط برای آزمودن چرخه سفارش است؛ صفحات و تراکنش‌هایش برچسب «آزمایشی» دارند و توکن نشست آن HMAC-امضاشده، یکتا و مبلغ‌دار است.

## تحویل فایل

- فایل محصولات در `storage/private/files` با نام تصادفی و ثبت `sha256` نگهداری می‌شود.
- `/download/:token` → کنترل: سفارش `paid`، grant لغونشده، انقضا، سقف تعداد، و **تطبیق مالک با کاربر واردشده**.
- هر دانلود در `download_logs` ثبت می‌شود. مدیر می‌تواند لینک تازه صادر کند.

## امنیت

- **CSRF**: توکن همگام‌ساز در همه فرم‌ها (در فرم‌های multipart از query چون body پیش از multer پارس نمی‌شود).
- **CSP**: `script-src 'self' + nonce`، `object-src none`، `frame-ancestors none`؛ هدر ویژه برای SVG های سرو‌شده.
- **XSS**: خروجی EJS به‌صورت پیش‌فرض escape؛ محتوای rich مدیر با `sanitize-html` ضدعفونی می‌شود.
- **Rate limiting**: ورود/ثبت‌نام (۲۰ در ۱۰ دقیقه)، checkout (۳۰)، فرم‌ها (۱۵)، دانلود (۱۰۰/ساعت).
- **Session fixation**: `session.regenerate()` در ورود/ثبت‌نام؛ کوکی `httpOnly` + `sameSite=lax`.
- **رمزها**: bcrypt cost 12؛ بازنشانی رمز با توکن هش‌شده ۳۰ دقیقه‌ای و باطل‌سازی نشست‌ها.
- **Secrets**: کلید پذیرنده زرین‌پال با AES-256-GCM در DB رمزنگاری می‌شود (کلید از `ENCRYPTION_KEY`/`.env`)؛ هیچ secret ای به کلاینت نمی‌رسد.
- **آپلود**: whitelist نوع/پسوند + سقف حجم + نام تصادفی؛ پیوست‌ها خصوصی.
- **Audit log**: ورودهای ناموفق، تغییرات مدیریتی، دانلودها، rate-limit ها و رویدادهای پرداخت در `audit_logs` (قابل مشاهده در `/admin/audit`).
- **حذف کنترل‌شده**: موجودیت‌های دارای سابقه مالی (محصول فروخته‌شده، کاربر دارای سفارش، کد استفاده‌شده) حذف سخت نمی‌شوند — غیرفعال می‌شوند.

## استقرار (Production)

1. سرور با Node ≥ 20؛ `NODE_ENV=production` و `PUBLIC_URL=https://yourdomain.com` را تنظیم کنید.
2. `SESSION_SECRET` و `ENCRYPTION_KEY` قوی تولید کنید (`openssl rand -hex 48` / `-hex 32`).
3. `data/` و `storage/` را روی دیسک پایدار (و در پوشش پشتیبان‌گیری) قرار دهید؛ در `.env` با `DATA_DIR`/`STORAGE_DIR` قابل جابه‌جایی‌اند.
4. پشت nginx/reverse-proxy: `app.set('trust proxy', 1)` فعال است؛ HTTPS را در proxy خاتمه دهید و در صورت نیاز `FORCE_SECURE_COOKIE=1`.
5. درگاه: در `/admin/settings` → زرین‌پال را انتخاب، Merchant ID را وارد و «آزمون اتصال» بزنید (حالت sandbox برای تست، production برای بهره‌برداری؛ دامنه callback باید در پنل زرین‌پال ثبت شده باشد).
6. SMTP را در `.env` پیکربندی کنید تا ایمیل‌های بازیابی رمز/اطلاع‌رسانی واقعاً ارسال شوند.
7. پشتیبان‌گیری: فایل DB (از `/admin/settings/backup` یا کپی `data/` پس از `PRAGMA wal_checkpoint`) + `storage/`.

### نمونه nginx

```nginx
server {
  listen 443 ssl http2;
  server_name example.com;
  client_max_body_size 320m;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```
