# 🔌 پل تلگرام به داشبورد CEO

این پوشه ورک‌فلوهایی است که **مخصوص خودِ داشبورد تو** ساخته شده‌اند — نه از مخزن عمومی برداشته شده‌اند.
هدف: باز کردن مسیر کامل «پیام مشتری → مشتری و لید در CRM → پاسخ فروش → برچسب فروش».

---

## جای خالی‌ای که این ورک‌فلو پر می‌کند

داشبورد تو یک ایجنت AI کامل دارد (`lib/agent/runner.js`) که:

| کار | وضعیت در داشبورد |
|---|---|
| گرفتن پیام مشتری از تلگرام | ✅ `POST /api/integrations/telegram/webhook` |
| ساخت مشتری + پیام + تایملاین | ✅ خودکار |
| تشخیص نیت خرید و ساخت لید | ✅ بر اساس کلمات `قیمت / موجود / خرید / سفارش` |
| ساخت پاسخ فروش با LLM | ✅ `agentRunner` (با `OPENAI_API_KEY` واقعی، بدون آن mock) |
| ذخیرهٔ پاسخ به‌عنوان پیام OUTBOUND | ✅ `metadata.via = 'agent'` |
| **فرستادن پاسخ برای مشتری در تلگرام** | ❌ **این کار انجام نمی‌شود** |

و اینجاست که ورک‌فلوی `01-telegram-to-crm-delivery.json` وارد می‌شود:

```
تلگرام ──► Webhook n8n ──► وبهوک CRM (مشتری + لید ساخته می‌شود)
                              │
                              ▼
                     ایجنت CRM پاسخ را می‌سازد و ذخیره می‌کند
                              │
                              ▼
     n8n پاسخ را برمی‌دارد ──► در تلگرام می‌فرستد ──► برچسب نیت می‌زند
```

## مسیر داده در ۲۰ گره

| # | گره | کار |
|---|------|-----|
| ۱ | `Webhook Telegram` | دریافت آپدیت تلگرام روی مسیر `/webhook/telegram-crm` |
| ۲ | `Normalize` | اعتبارسنجی + رد کردن پست‌های خودِ کانال و پیام ربات‌ها |
| ۳ | `Is Customer` | اگر پیام از مشتری نبود → `Respond Skip` (۲۰۰) |
| ۴ | `CRM Webhook` | فوروارد بدنهٔ دست‌نخوردهٔ تلگرام با هدر سکرت به CRM |
| ۵ | `Read CRM Result` | خواندن `customerId / leadId / duplicate` + تشخیص نیت خرید |
| ۶ | `CRM OK` | خطا در CRM؟ → `Respond Error` (۵۰۰) |
| ۷ | `Duplicate` | آپدیت تکراری؟ → `Respond Duplicate` (۲۰۰، بی‌اثر) |
| ۸ | `CRM Login` | گرفتن توکن JWT با شماره و رمز CEO |
| ۹ | `Wait Agent` | ۷ ثانیه صبر تا ایجنت داخلی CRM پاسخ را بسازد |
| ۱۰ | `Fetch Messages` | خواندن پیام‌های مشتری از CRM |
| ۱۱ | `Pick Reply` | برداشتن آخرین پیام `OUTBOUND` با `metadata.via = 'agent'` |
| ۱۲ | `Has Reply` | اگر پاسخ آماده نبود → `Respond NoReply` (۲۰۰) |
| ۱۳ | `Send Telegram` | **فرستادن پاسخ در تلگرام** (`/api/integrations/telegram/send`) |
| ۱۴ | `Tag Customer` | زدن برچسب: `استعلام قیمت` / `استعلام موجودی` / `علاقه‌مند به خرید` |
| ۱۵ | `Respond Done` | پاسخ نهایی ۲۰۰ با `customerId, leadId, tag` |

سه گرهٔ آخر **کل زنجیرهٔ پول** را می‌سازند: مشتری ثبت می‌شود، پاسخ می‌گیرد و برای تیم فروش برچسب می‌خورد.

## راه‌اندازی (۵ دقیقه)

### ۱) ایمپورت
`Import from File` در n8n → فایل `01-telegram-to-crm-delivery.json`

### ۲) چهار مقدار را عوض کن
| کجا | چه بگذاری |
|-----|-----------|
| همهٔ گره‌های `httpRequest` | به‌جای `http://localhost:3000` آدرس واقعی داشبوردت (دامنه یا IP) |
| هدر `X-Telegram-Bot-Api-Secret-Token` | همان مقدار `TELEGRAM_WEBHOOK_SECRET` در `.env` داشبورد |
| گرهٔ `CRM Login` | شماره (`phone`) و رمز (`password`) حساب CEO |
| `Wait Agent` | اگر سرورت کند است، از ۷ ثانیه به ۱۵ ثانیه ببر |

> 🔐 رمز CEO داخل فایل ورک‌فلو ذخیره می‌شود. اگر این برایت مهم است، در n8n یک Credential از نوع
> `Header Auth` بساز (`Authorization: Bearer …`) و به‌جای گام لاگین از توکن ثابت استفاده کن.

### ۳) وبهوک تلگرام را به n8n وصل کن
```bash
curl -X POST "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<آدرس-n8n-تو>/webhook/telegram-crm" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```
بررسی: `curl "https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo"`

> ⚠️ وبهوک داشبورد (`/api/integrations/telegram/webhook`) دیگر نباید مستقیم به تلگرام وصل باشد —
> چون از این به بعد n8n نقطهٔ ورود است و خودش آپدیت را به CRM می‌دهد.
> (اگر هر دو فعال باشند، هر پیام دو بار پردازش می‌شود؛ هرچند idempotency از پیام تکراری جلوگیری می‌کند.)

### ۴) فعال کن و تست کن
```bash
curl -X POST "https://<آدرس-n8n-تو>/webhook/telegram-crm" \
  -H "Content-Type: application/json" \
  -d '{"update_id":900001,"message":{"message_id":55,
       "from":{"id":700123456,"is_bot":false,"first_name":"مریم"},
       "chat":{"id":700123456,"type":"private"},
       "text":"سلام، قیمت بسته تولید محتوا چنده؟"}}'
```
خروجی موفق:
```json
{"success":true,"replied":true,"customerId":"cus_…","leadId":"lead_…","tag":"استعلام قیمت","telegramSentOk":true}
```

## پاسخ‌های ممکن این ورک‌فلو

| پاسخ | معنی | کار تو |
|------|------|--------|
| `replied: true` | همه چیز کار کرد | تمام ✅ |
| `skipped: true` + `reason` | پست خودِ کانال یا پیام ربات بود | طبیعی است |
| `duplicate: true` | تلگرام همین آپدیت را دوباره فرستاد | طبیعی است (idempotency) |
| `step: "crm-webhook"` (۵۰۰) | CRM جواب نداد یا سکرت غلط بود | `TELEGRAM_WEBHOOK_SECRET` و آدرس را چک کن |
| `replied: false` + «هنوز آماده نشده» | ایجنت CRM بیش از ۷ ثانیه طول کشید | `Wait Agent` را زیاد کن |

## نکات مهم

1. **پاسخ ایجنت با mock هم کار می‌کند.** اگر `OPENAI_API_KEY` روی سرور داشبورد نگذاری، ایجنت از
   `mockLLM` قطعی استفاده می‌کند و باز هم پاسخ می‌دهد. برای پاسخ واقعی، کلید را در `.env` داشبورد بگذار.
2. **پاسخ‌ها دوبار فرستاده نمی‌شوند؟** فقط اگر ابزار تلگرام ایجنت (`lib/agent/toolsExecutor.js`) هم فعال باشد
   ممکن است دو بار برود. اگر این اتفاق افتاد، آن ابزار را غیرفعال کن تا فقط n8n تحویل‌دهنده باشد.
3. **تلگرام و وبهوک کند:** کل زنجیره ~۹ ثانیه طول می‌کشد. اگر نگران timeout تلگرام هستی، `Wait Agent` را کم کن
   یا دو ورک‌فلو جدا کن (ورود فوری + تحویل با تأخیر).
4. **برای اینستاگرام هم همین الگو کار می‌کند:** فقط گرهٔ اول را به وبهوک اینستاگرام داشبورد عوض کن
   (امضای `X-Hub-Signature-256` را باید با HMAC در یک گرهٔ Code بسازی).
